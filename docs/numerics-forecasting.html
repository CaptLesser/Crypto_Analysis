forecasting overview

Numeric forecasting overview

Numerics Forecasting produces future numeric target estimates rather than state labels. The public source groups the work into tabular machine-learning, neural, Bayesian, and statistical families.

This page emphasizes model families, targets, horizons, and Test workflow stages. It does not claim model accuracy, trading utility, deployment status, or generated forecast values.

model families

Model families and methods

The public registry files name the model families and source entry points. Presenting them as a grouped table is clearer than making the orchestration package the main topic.

Seasonality is not a standalone feature family on this page. It is mentioned only where source code resolves or consumes a usable seasonality profile.

targets and horizons

Targets and horizons

A target is the supervised forecasting value the model is trained to estimate. A horizon is the future lead time, in minutes, for that target.

The shared numeric target mapping and tabular horizon matrix expose the public target names and source-visible horizon coverage.

test workflow

Test workflow stages

The Test workflow runs staged evaluation before selected profiles are used by orchestration workflow code. The exact modules vary by family, but the stage shape is consistent across tabular, neural, Bayesian, and statistical source.

The public page should summarize stage purpose and source files rather than listing every command-line flag.

Test workflow stages
StagePurposeRepresentative source
Stage 0: profile sweepBuild candidate profiles or candidate combinations for the family and record which tasks, horizons, intervals, and assets are viable for deeper testing.tabular_numeric_stage0_profile.py, neural_numeric_stage0_profile.py, bayesian_numeric_stage0_profile.py, stats_numeric_stage0_profile.py
Stage 1: feature experimentEvaluate feature or formulation choices. Tabular and neural families evaluate feature candidates; Bayesian and statistical stages capture family-specific formulation and seasonality/window evidence where relevant.family-specific *_feature_experiment modules and stats_stage_runner.py
Stage 2: numeric scaling testRun bounded scaling tests for surviving candidates, collect fit and prediction metadata, and verify that the family can run across the selected numeric combinations.family-specific *_numeric_scaling_test modules
Stage 3: tuningRun bounded Optuna tuning for surviving combinations and collect combo results, trials, unit metrics, summaries, and representative samples.family-specific *_numeric_optuna_tuning modules

orchestration workflow

Orchestration workflow

Orchestration workflow source consumes selected model profiles and family-specific defaults to define numeric forecast and evaluation rows. The public page presents this as source architecture and contract shape, not as a runtime claim.

The orchestration package remains useful as a source link, but it is not the main content headline for Numerics Forecasting.

Orchestration workflow by family
FamilyOrchestration workflow shapeSource notes
TabularModel specs resolve default or requested interval/horizon/task combos, runtime config keys, prediction prefixes, and family-specific output tags.XGBoost shares approved default combo policy through numeric_forecast_profiles.py; other tabular families resolve defaults from their numeric profile modules.
NeuralFamily registries route LSTM, TCN, and N-BEATS to numeric entry points and family root names.Shared neural runners and profile modules own the sequence-model execution details.
BayesianThe shared Bayesian runner uses model specs, quantile metadata, optional exogenous/factor inputs, and seasonality only where the selected profile or module spec enables it.DLM/TVP exposes seasonal-strength profile parameters; shared runner records seasonality mode and period when usable.

Terms

Plain-language source notes.

target
The supervised future value a model is trained to estimate, such as future_log_return or future_realized_vol.
horizon
The future lead time, in minutes, associated with a target.
model family
A source grouping for related forecasting implementations and helper files.
seasonality profile
A model-side seasonal input resolved by specific statistical or Bayesian source paths when the profile is usable; it is not presented as a standalone feature page topic.
