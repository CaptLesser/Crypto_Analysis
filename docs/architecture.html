source boundary

Public source boundary

The public source guide is organized around selected source modules rather than generated data or operational records.

The current allowlist points to feature modules, forecasting modules, statistical modules, regime modules, and selected test-lane study code.

  • src
  • src

source layers

Source layers

Feature source lives under src/features and src/regimes feature subpackages. This guide presents Scalar Features, Regime Features, and Relationship Features as the public feature families.

Forecasting source is split between common helpers, machine-learning families, statistical families, and an orchestration package under src/forecasting.

Regime source lives under src/regimes and includes core contracts, market-state, asset-state, cross-asset, relationship-discovery, regime-feature, and study modules.

The site describes those source layers as repository organization; it does not assert private runtime coverage or expose generated artifacts.

branch lanes

Branch lanes

The main branch is the primary public source lane.

The pipeline_test branch is a public branch for selected test-lane modules, including visible experiment, scaling, tuning, and asset-state study code.

Branch-lane wording should remain explicit so readers do not infer that test-lane files are generated outputs or that private data is published.

  • main branch
  • pipeline_test branch

excluded surfaces

Excluded surfaces

The public site should not represent private data, generated outputs, model files, run logs, local reports, or local machine paths as part of the public source guide.

Any claim about runtime behavior should be backed by reviewed public source or a separate approved public report.

The architecture page should stay at source-layer level: inputs, features, labels, forecasts, and public boundaries are described conceptually, not through private pipeline state.

conceptual flow

Conceptual flow

The public architecture can be read as a conservative flow: source-visible feature builders feed derived feature concepts, regime modules describe state-label concepts, and forecasting modules organize numeric forecast families.

The source guide presents repository organization and public boundaries without exposing generated runtime artifacts.

  • src/forecasting
