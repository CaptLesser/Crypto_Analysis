regime definitions

Market, asset, and cross-asset regimes

The regime source tree has three public state workflows: Market State, Asset State, and Cross-Asset State. Each workflow interprets a different behavioral scope and has its own axes, feature pools, candidate methods, and planning contracts.

The public site should describe the workflow shape and output contracts without claiming current active labels or publishing generated state rows.

Regime workflow scopes
WorkflowPlain-language interpretationAxes or familiesSource contract
Market StateInterprets broad conditions across the asset universe: whether the market is rising or falling together, how broad participation is, how dispersed returns are, how correlated assets are, how volatile the market is, and whether leadership is concentrated.Core contract axes: market, breadth, dispersion, correlation, market_vol, leadership. Test workflow panels also include return, volatility, breadth, dispersion, correlation, liquidity/activity, stress, stable-peg stress, and speculative sidecar panels.src/regimes/core/contracts.py and src/regimes/market_state/test_branch_campaign.py

Source labels use cluster assignments plus plain labels, confidence, and intensity fields.trend, vol, activity; bands are micro, meso, and macro with 30, 240, and 1440 minute ceiling intervals.src/regimes/contracts.py and src/regimes/asset_state/feature_pools.py
Cross-Asset StateInterprets how each asset behaves relative to anchors, core baskets, peer strength, concentration, entropy, and residual peer signals. The core contract calls this relative_state; the source folder for the current workflow is cross_asset_state.Core relative-state axes: relative, beta, correlation, relative_strength, relative_dispersion. Cross-asset feature families: anchor_core_exposure, peer_strength_stability, relationship_concentration_entropy, residual_peer_signal.src/regimes/cross_asset_state/feature_families.py and src/regimes/cross_asset_state/method_universe.py

test workflow

Test workflow

The Test workflow is where the source compares candidate feature panels, preprocessing choices, dimensionality-reduction choices, clustering methods, and profile evidence before any planning workflow step.

Raw clustering outputs should be treated as cluster assignments until a workflow produces an interpreted profile or label contract.

planning workflow

Planning workflow

The source-visible planning workflow starts after profile selection. It validates selected profile manifests, resolves the input edge, builds timestamp plans, creates planning units, and emits job-matrix and telemetry payloads.

This page presents planning contracts as source architecture. It does not claim that the public site publishes generated labels or runtime rows.

Planning workflow outputs
WorkflowPlanner inputsPlanned outputsLabel or row contract
Asset StateSelected asset-state profile manifest plus input edge and profile artifact hash.Planning units, selected/skipped counts, job matrix summary, reuse-cache telemetry, clamp policy, refit cadence, normalized lineage checks.Asset label rows include ts, asset, band, ceiling_interval_min, each trend/vol/activity cluster_id, label, confidence_pct, intensity_pct, and feature_schema_hash.
Market StateSelected market-state profiles and masked/skipped cells from the market-state selected-profile artifact.Planning units for selected and masked-unavailable cells, job matrix summary, per-axis target keys, input-edge telemetry, and profile lookup metadata.Wide market-state rows are keyed by ts, band, and profile_id, with per-axis assignment, id, score, confidence, and status columns.
Cross-Asset StateSelected, diagnostic-only, and masked cross-asset profiles plus relationship-input freshness checks.Planning units by asset, relationship feature family, and band; relationship freshness summary; job matrix summary; selected, diagnostic-only, and masked counts.Selected profile records include asset_id, relationship_feature_family, band, profile_id, method_family, feature_columns, state_count, label health, relationship snapshot lineage, and support metadata.

Terms

Plain-language source notes.

behavioral axis
The conceptual domain being evaluated or clustered, such as trend, volatility, activity, breadth, dispersion, or relationship exposure.
cluster assignment
The raw result of a clustering method before a workflow interprets it as a state label.
profile
A selected method and configuration record with evidence, lineage, target keys, and planner metadata.
Planning workflow
The source-visible planning path that consumes selected profiles and prepares job matrices and telemetry; the public site does not publish generated runtime rows.

Source-only public guide. Generated data, model artifacts, run logs, and private operational records are outside this site.
